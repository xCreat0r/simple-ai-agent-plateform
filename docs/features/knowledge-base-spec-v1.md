> **Version:** 1.1
> **Status:** 已实现 — M1 大部分已落地（PostgreSQL pgvector / workers-ai·dashscope 嵌入 / Worker 内 unpdf 本地解析 PDF）
> **Owner:** Platform Team
> **Last Updated:** 2026-08-08
> **本文档为需求契约**：描述当前代码的实际行为，并保留可验收的需求与指标。与代码不一致处**以代码实现为准**，实现细节见 [architecture.md](../architecture.md)。未实现项在文内标注。

## 1. 背景与目标

### 1.1 背景

当前 Agent 仅能依赖通用大模型的知识回答用户问题，无法感知用户的私有资料（企业内部文档、个人笔记、产品手册等）。这导致：

- 回答缺乏领域准确性，易产生幻觉
- 无法回答"只存在于用户资料中"的问题
- 企业级知识沉淀与复用能力缺失

### 1.2 目标

让 Agent 能够：

1. 基于用户上传的私有文档回答问题
2. 回答时引用具体来源，支持溯源与可信度判断
3. 支持多文档、多知识库的规模化组织
4. 保证多租户数据隔离（A 用户资料不可被 B 用户访问）

### 1.3 成功指标

> 用于判断"功能是否达成目标"的量化标准，M1 验收时须提供实测数据。

| 编号 | 指标 | 目标值 | 测量方式 |
|------|------|--------|---------|
| SI-01 | 检索召回率@topK | 相关分块在 topK 内的命中率 ≥ 80% | 用标注好的 QA 测试集，查询后检查命中 |
| SI-02 | 检索精确率@topK | topK 结果中相关分块占比 ≥ 60% | 同上，人工/规则判定相关性 |
| SI-03 | 无关查询抑制率 | 明显无关问题不触发知识库注入的比例 ≥ 90% | 无关问题样本集 |
| SI-04 | 文档处理成功率 | 含文字层的合法文档处理成功（status=ready）≥ 98% | 处理日志统计 |
| SI-05 | 回答来源可溯源率 | 基于知识库的回答中，引用来源文件的占比 ≥ 90% | 抽样人工评估 |
| SI-06 | 数据隔离违规数 | 跨用户访问测试中违规数为 0 | 安全回归测试 |

> 指标基线说明：SI-01/02/03 依赖检索质量，M1 至少应建立小规模标注测试集（≥ 50 条查询）作为基线；后续随文档量增长持续校准。

## 2. 术语

| 术语 | 定义 |
|------|------|
| 知识库 (Knowledge Base) | 用户的文档集合容器，可绑定到 Agent |
| 文档 (Document) | 用户上传的单个文件（PDF / TXT / Markdown 等） |
| 分块 (Chunk) | 文档被切分后的最小检索单元 |
| 向量化 (Embedding) | 将文本转换为数值向量以支持语义相似度计算 |
| RAG | 检索增强生成：先检索相关分块，再作为上下文供模型回答 |

## 3. 用户故事

| ID | 作为 | 我希望 | 以便 |
|----|------|--------|------|
| US-01 | 平台用户 | 创建/删除/重命名知识库 | 分类管理自己的资料 |
| US-02 | 知识库管理员 | 上传多种格式文档 | 系统解析并建立索引 |
| US-03 | 知识库管理员 | 查看文档处理状态与失败原因 | 知道文档何时可用、为何失败 |

| US-08 | 平台用户 | 限制存储用量 | 控制资源成本 |

## 4. 功能需求

> 优先级：**MUST**（必须）/ **SHOULD**（应该）/ **MAY**（可以）

### FR-01 知识库管理

- **MUST**：创建知识库（需名称）
- **MUST**：删除知识库（级联删除其下所有文档与分块）
- **SHOULD**：重命名知识库
- **MUST**：知识库归属当前用户，其他用户不可见、不可操作

### FR-02 文档上传

- **MUST**：支持上传 PDF、纯文本、Markdown 格式
- **SHOULD**：支持 CSV、JSON 等结构化文本
- **MAY**：支持 DOCX / XLSX（依赖解析能力）
- **MUST**：上传时校验文件大小上限与用户存储配额
- **MUST**：拒绝不支持的格式，返回明确错误
- **MUST**：上传接口立即返回，向量化异步处理（文本解析为同步；PDF 需调用外部解析服务）

### FR-03 文档处理管线

上传后按以下管线异步处理，每个文档有独立状态：

```
解析文本 → 文本分块 → 向量化 → 写入向量存储
```

- **MUST**：文档状态至少包含：处理中 / 可用 / 失败
- **MUST**：失败时记录可读的错误原因（供前端展示）
- **MUST**：处理超时（>30 分钟）卡在 `processing` 的文档由定时任务回收，标记为 `failed`（cron 每 6 小时执行）
- **SHOULD**：处理完成/失败后，前端能感知状态变化（已实现：前端轮询）
- **MAY**：支持重新处理失败文档（**未实现**）
- 解析失败（如扫描件 PDF）发生在落库之前，直接返回 4xx 且不产生文档记录（见 AC-08）

### FR-04 文本分块

- **MUST**：将长文档切分为语义较完整的块
- **SHOULD**：相邻块保留少量重叠，避免语义断裂
- **SHOULD**：分块参数（块大小、重叠量）可配置
- **MUST**：块内容可追溯回源文档

### FR-05 向量化

- **MUST**：为每个分块生成固定维度的向量
- **MUST**：查询文本与分块使用同一向量化模型（保证可比性）
- **SHOULD**：向量化服务可替换（多 provider 抽象）
- **SHOULD**：批量向量化以提高吞吐

> 实现现状：通过 `EMBEDDING_PROVIDER` 切换 `workers-ai`（默认）/ `dashscope` / `mock`，维度固定 1024。**任何 provider 失败均将文档标记 `failed`，不再自动降级**（mock 仅在显式设置 `EMBEDDING_PROVIDER=mock` 时用于本地链路调试，无语义）。**注意**：不同模型生成的向量处于不同语义空间，切换 provider 后历史分块向量与新查询向量不可直接比较，须重建知识库索引（见 OQ-06）。

### FR-06 语义检索

- **MUST**：给定查询，返回与查询语义最相关的分块（按相似度排序）
- **MUST**：返回的分块附带来源文档信息
- **SHOULD**：支持相似度阈值过滤，低于阈值视为"无关"
- **SHOULD**：支持配置检索数量上限 (topK)
- **MAY**：支持多知识库聚合检索

### FR-07 Agent 绑定知识库

- **MUST**：Agent 可绑定零个或多个知识库
- **MUST**：仅允许绑定当前用户自己的知识库
- **MUST**：对话时自动检索绑定知识库，将相关分块作为上下文

### FR-08 对话增强 (RAG)

- **MUST**：将检索到的分块注入对话上下文，指导模型回答
- **MUST**：注入内容包含来源文件名，模型应引用来源
- **SHOULD**：检索无结果时，对话回退为普通回答（不注入）
- **SHOULD**：检索/嵌入异常时，对话回退为普通回答，不中断（已实现：检索失败仅告警并跳过注入）
- **SHOULD**：不暴露无关知识库的内容给模型

### FR-09 存储配额

- **MUST**：每个用户有存储上限（可配置）
- **MUST**：上传前校验，超限时拒绝并给出已用量/上限
- **MUST**：删除文档后释放对应配额

> 实现口径：配额按文档**原始文件字节**（`size_bytes`）累加统计（未计入向量与分块文本的额外存储），删除文档/知识库后级联清理并自动释放配额。

## 5. 非功能需求

| 编号 | 类别 | 需求 |
|------|------|------|
| NFR-01 | 性能 | 上传接口应在 1s 内返回（向量化异步；文本解析为同步，PDF 本地解析，基线另行测量） |
| NFR-02 | 性能 | 单文档处理时间应小于 60s（典型大小） |
| NFR-03 | 性能 | 对话检索延迟应 < 500ms（不含 LLM 生成） |
| NFR-04 | 安全 | 所有知识库/文档接口需鉴权；数据按租户隔离 |
| NFR-05 | 安全 | 不得在日志/错误中暴露文件内容或密钥 |
| NFR-06 | 可靠性 | 处理失败不影响其他文档/知识库 |
| NFR-07 | 可观测 | 文档处理状态可查询；失败原因可追溯 |
| NFR-08 | 可配置 | 分块参数、检索参数、配额、大小限制均支持配置（`src/lib/config.ts`） |
| NFR-09 | 可扩展 | 向量化 provider、解析能力应可替换/扩展（provider 切换后历史向量失效，须重建索引） |

### NFR 验收方法

> NFR 须有对应验收条款，否则指标不可验证。下表给出每项指标的验证方式与数据量级。

| 编号 | 验证方式 | 数据量级 |
|------|---------|---------|
| NFR-01 | 压测工具（如 k6/curl 并发）测上传接口 P95 响应时间 | 100 次请求 |
| NFR-02 | 上传典型大小文档（如 1MB PDF），记录处理完成耗时 | 单文档 × 10 份 |
| NFR-03 | 构造含 >1000 分块的知识库，测对话检索耗时 | 100 次查询 |
| NFR-04 | 跨用户访问回归测试（A 访问 B 资源全部返回 401/404） | 全接口矩阵 |
| NFR-05 | 代码审查 + 日志抽查，确认无内容/密钥打印 | 静态检查 + 运行日志 |
| NFR-06 | 单文档处理失败场景下，其余文档/知识库功能正常 | 故障注入测试 |
| NFR-07 | 查询文档状态接口返回完整状态与失败原因 | 正常 + 失败样本 |
| NFR-08 | 修改配置后重启，行为随之变化 | 配置项逐一验证 |
| NFR-09 | 更换 embedding provider，功能不受影响 | provider 切换测试 |

## 6. 数据模型（概念层）

> 以下为概念模型，不绑定具体存储实现（关系型 / 向量库独立）。

```
User (1) ──< (N) KnowledgeBase
KnowledgeBase (1) ──< (N) Document
Document (1) ──< (N) Chunk
Agent (N) >──< (M) KnowledgeBase   (多对多绑定)

Document:  文件名 / 大小 / 处理状态 / 失败原因 / 上传时间
Chunk:     所属文档 / 文本内容 / 在文档内的顺序 / 可追溯回源
```

> 概念层只描述业务语义，不包含存储实现细节（如向量字段、时间戳、主键形式）；具体存储由开发阶段决定。

**数据隔离规则**：所有文档/知识库的访问路径都必须经过"所属用户"校验，杜绝横向越权。

## 7. API 契约

> 除明确标注外，所有接口需 `Authorization: Bearer <token>`，数据按当前用户隔离。

### KB API

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/knowledge` | 创建知识库 |
| GET | `/api/knowledge` | 知识库列表 |
| GET | `/api/knowledge/:id` | 知识库详情 |
| DELETE | `/api/knowledge/:id` | 删除知识库 |
| PATCH | `/api/knowledge/:id` | 重命名知识库 |
| POST | `/api/knowledge/:id/documents` | 上传文档（multipart） |
| GET | `/api/knowledge/:id/documents` | 文档列表（含状态/分块数） |
| DELETE | `/api/knowledge/:id/documents/:docId` | 删除文档 |
| GET | `/api/knowledge/:id/documents/:docId/content` | 查看文档内容 |

### 请求 / 响应示例

**创建知识库**

```
POST /api/knowledge
{ "name": "产品手册" }

→ 201
{ "id": "kb_123", "name": "产品手册", "createdAt": "..." }
```

**上传文档**（返回立即，异步处理）

```
POST /api/knowledge/kb_123/documents   (multipart/form-data: file=...)

→ 202
{ "id": "doc_456", "filename": "手册.pdf", "chunkCount": 12, "status": "processing" }
```

**文档列表**（含状态与分块数）

```
GET /api/knowledge/kb_123/documents

→ 200
[
  { "id": "doc_456", "filename": "手册.pdf",
    "status": "ready", "chunkCount": 12, "createdAt": "..." }
]
```

## 8. 验收标准

> BDD 风格：Given / When / Then。所有标准应可自动化验证。

### AC-01 创建知识库

- Given 用户已登录
- When 提交创建知识库请求（含名称）
- Then 返回 201，且列表接口包含新知识库
- And 返回的知识库归属于该用户

### AC-02 数据隔离

- Given 用户 A 拥有知识库 kb_1
- When 用户 B 访问 `/api/knowledge/kb_1`
- Then 返回 404（不暴露存在性）
- And 用户 B 无法对该知识库做任何读写操作

### AC-03 上传合法文档

- Given 上传合法 `.md` 文件（含可读文本）
- When 处理完成
- Then 文档状态为 `ready`
- And 文档分块数 >= 1
- And 每个分块内容为可读文本

### AC-04 上传 PDF

- Given 上传含文字层的 PDF
- When 处理完成
- Then 文档状态为 `ready`
- And 分块包含 PDF 中的文字内容

### AC-05 拒绝非法格式

- Given 上传 `.exe` 文件
- When 提交上传
- Then 返回 400 且错误信息包含"不支持的文件类型"
- And 不产生任何文档记录

### AC-06 拒绝超限文件

- Given 文件大小超过配置上限
- When 提交上传
- Then 返回 400 且错误信息包含"文件过大"

### AC-07 存储配额

- Given 用户已用存储 + 新文件大小超过配额
- When 提交上传
- Then 返回 413 且错误信息包含已用量与上限

### AC-08 扫描件处理

- Given 上传扫描件 PDF（无文字层）
- When 提交上传
- Then 返回 422，错误信息为可读原因（如"未提取到可读文本（可能是扫描件）"）
- And 不产生任何文档记录
- And 不影响其他文档

> 注：解析发生在文档落库之前，失败直接返回 4xx 而非标记 `failed`（实现现状）。若需"失败文档可查"，见里程碑 M2 的重新处理能力。

### AC-09 Agent 绑定与检索

- Given Agent 已绑定包含相关内容的知识库
- When 用户提问相关问题
- Then 回答基于文档内容，且引用来源文件名
- And 注入的上下文包含检索到的分块

### AC-10 无绑定时回退

- Given Agent 未绑定任何知识库
- When 用户提问
- Then 对话正常回答，且不注入检索内容

### AC-11 无关问题

- Given Agent 绑定知识库，但问题与文档内容无关
- When 用户提问
- Then 回答不强行引用知识库内容（阈值过滤生效）

### AC-12 检索相关性（质量）

- Given 知识库含"退款政策"相关文档
- When 查询语义相近的问题（如"退货怎么办理"）
- Then 返回分块中包含"退款政策"相关内容
- And 该分块通过配置阈值过滤（实现为 cosine 距离 ≤ `KNOWLEDGE_SIMILARITY_THRESHOLD`，默认 0.6，越小越严格）

### AC-13 检索排序（质量）

- Given 知识库含多份文档，其中 A 文档与查询高度相关、B 文档弱相关
- When 执行检索
- Then 返回结果按相似度降序排列，A 文档分块排在 B 之前

### AC-14 检索质量指标（质量）

- Given 已建立 ≥ 50 条的标注 QA 测试集
- When 运行检索回归
- Then SI-01 召回率@topK ≥ 80%，SI-02 精确率@topK ≥ 60%，SI-03 无关抑制率 ≥ 90%

### AC-15 删除级联

- Given 知识库含多个文档与分块
- When 删除该知识库
- Then 文档与分块全部移除（无孤儿数据）
- And 配额释放

### AC-16 删除文档

- Given 知识库含文档 D
- When 删除 D
- Then D 及其分块移除，其余文档不受影响

### 用户故事覆盖矩阵

> 保证每个用户故事都有对应验收标准，可追踪"故事是否被完整覆盖"。

| 用户故事 | 覆盖的验收标准 |
|----------|---------------|
| US-01 创建/删除/重命名知识库 | AC-01, AC-15（重命名未实现，无 AC） |
| US-02 上传多种格式文档 | AC-03, AC-04, AC-05, AC-06 |
| US-03 查看处理状态与失败原因 | AC-03, AC-04, AC-08（解析失败返回可读错误） |
| US-04 删除单个文档 | AC-16 |
| US-05 绑定知识库到 Agent | AC-09, AC-10 |
| US-06 提问得到文档回答 | AC-09, AC-11, AC-12, AC-13 |
| US-07 看到回答引用的来源 | AC-09 |
| US-08 限制存储用量 | AC-07 |

## 9. 边界与异常

| 场景 | 期望行为 |
|------|---------|
| 上传空文件 | 400「文件内容为空」 |
| 上传空请求体 | 400 |
| 访问不存在的知识库/文档 | 404 |
| 未携带 token / token 失效 | 401 |
| 向量化服务不可用 | 任何 provider 失败均将文档标记 `failed`（不再降级 mock），错误可读；不崩溃。本地调试如需无语义链路，显式设 `EMBEDDING_PROVIDER=mock` |
| 上传 PDF 解析失败/超时/页数超限 | 上传返回 4xx，错误信息可读（Worker 内 `unpdf` 本地解析：页数上限 `KNOWLEDGE_MAX_PDF_PAGES`，30s 超时，`maxImageSize` 资源防护） |
| 并发上传 | 各文档独立处理，互不影响 |
| 文档处理中删除该文档/知识库 | 删除操作生效；后台嵌入任务不主动取消，写入时撞外键失败，无孤儿分块残留（会产生失败日志） |
| 超长文件名 | 正常存储展示，不注入问题 |
